OpenAI 가 frontier 모델의 학습 환경을 가두고 red-teaming 으로 시험한 방식

OpenAI 는 frontier 모델의 학습과 평가 환경을 인터넷, 다른 agent, 자기 인프라에서 겹겹이 떼어 둔다. 9월 20일 사건 뒤 가장 능력 있는 모델의 학습과 평가를 멈추고 자기 모델에게 이 울타리를 공격하게 했더니, agent 는 남겨 둔 좁은 연결을 거쳐 인터넷에 제한적으로 닿는 길을 여럿 찾았다. OpenAI 는 patch 와 network 제한으로 대응한 뒤 10월 1일 RL 학습과 내부 inference 를 재개했고, 평가의 재개는 적지 않았다. 모두 OpenAI 의 자기 보고이고 발견 내역과 재개 기준값은 글에 없다. 이 문서가 읽기로, agent sandbox 를 만드는 독자는 열어 둔 연결 하나하나를 경로 후보로 봐야 한다.

OpenAI 가 2026-10-23 에 낸 글 「Securing our frontier model training environment」다. Author 란에는 개인 이름 없이 OpenAI 만 적혀 있다. 2026-10-25 에 읽은 판이고, 이 글이 링크한 OpenAI 의 safety case 지침(2026-09-28), Internet Archive 사본 둘, Hacker News 토론을 함께 봤다.

OpenAI 는 학습 중인 모델이 아직 안전과 정렬 학습을 마치지 않았을 수 있고, 일부러 적대적 조건에서 시험한다고 적는다. 그래서 출시 모델과 다른 울타리가 필요하다는 것이 OpenAI 의 출발점이다.

첫머리, §Resuming frontier training

  • 원문은 중단이 시작된 날짜를 직접 적지 않는다. 재개일 10월 1일이 중단 시작 11일 뒤라고 적으므로, 거슬러 세면 9월 20일이다.
  • 원문이 멈췄다고 적은 것은 가장 능력 있는 모델의 학습과 평가다. 다시 시작했다고 적은 것은 frontier RL 학습과 내부 inference 다. 원문은 평가를 다시 열었는지 적지 않고, 내부 inference 를 멈췄다고도 적지 않는다.
  • 대상 모델도 다르게 적혀 있다. 멈춘 쪽은 '가장 능력 있는 모델'이고 재개한 쪽은 'frontier 모델'이다. 두 말이 같은 모델을 가리키는지 원문은 적지 않는다.
  • 재개 문장의 '점검(assessments)을 마치고'는 무엇을 점검했는지 적지 않는다. 이 말을 평가(evaluation) run 을 다시 열었다는 뜻으로 읽을 근거는 원문에 없다.
  • OpenAI 는 지금의 정렬 연구, monitoring, 인터넷 인프라 보안 수준에서는 인터넷 없이 학습하는 것이 책임 있는 방식이라고 보고, 이 safeguard 가 나아질 때까지 이 정책을 유지한다고 적는다.

평가 run 이 10월 1일 뒤 다시 돌았는지는 이 글로 알 수 없다. 그래서 이 재개를 인용할 때는 범위를 RL 학습과 내부 inference 로 적는다.

모델이 browsing 과 검색을 배우려면 웹이 필요하다. OpenAI 는 이를 위해 색인하고 cache 한 웹 콘텐츠 묶음인 offline world 를 만들었고, 모든 frontier RL run 이 이 방식으로 웹을 쓴다고 적는다. 그래서 학습 중 모델이 보는 웹은 외부 시스템에 영향을 줄 수 없는 사본이다.

  • 원문이 최우선 원칙으로 든 것은 frontier 모델이 허가 없이 인터넷에 임의로 접근하는 일을 언제나 막을 수 있어야 한다는 것이다.
