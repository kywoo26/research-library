teamai-cli 가 팀의 agent 설정을 git 저장소와 PR 로 나눠 주는 방식

teamai-cli 는 팀의 skill, rule, agent, hook, MCP 설정을 git 저장소 하나에 두고 팀원 각자의 AI coding 도구에 나눠 주는 CLI 다. 설정을 바꾸는 사람은 branch 와 PR 로 올리고, 받는 사람은 세션이 시작될 때 pull 로 받는다. 코드를 읽은 결과로는 팀이 이 PR 리뷰를 agent 설정의 배포 승인으로 다뤄야 한다. 멤버의 오래된 사본이 팀의 변경을 되돌리는 push 를 도구는 경고만 하고 올린다. agent 가 workflow 로 바꾼 코드도 PR 까지만 가고, learning 은 리뷰 없이 쌓인다.

Tencent 의 GitHub 조직에 있는 오픈소스 저장소 Tencent/teamai-cli 의 코드와 저장소 안 문서다(MIT, package.json 0.22.0). 2026-10-25 커밋 13c891e 를 기준으로 읽었고, README 와 LICENSE 는 만든 팀을 따로 밝히지 않는다.

pull 은 멤버가 고친 사본을 덮지 않고 남긴다

pull 은 파일을 쓸 때마다 그 bytes 의 sha256 을 기록해 둔다. 다음 pull 은 디스크의 파일을 이 기록과 이번에 쓸 팀 판에 비교해서 쓸지 남길지 정한다.

디스크의 사본pull 이 하는 일멤버가 겪는 일
파일이 없다팀 판을 쓴다지운 사본은 다음 pull 에 돌아온다
기록과 같다팀 판으로 바꿔 쓴다팀의 변경이 그대로 들어온다
기록과도 이번 팀 판과도 다르다남긴다. 팀 판도 바뀌었으면 teamChanged 로 표시만 한다멤버의 편집이 남고 팀의 변경은 들어오지 않는다
기록이 없다팀 저장소 이력의 어느 판을 teamai 가 그린 결과와 같을 때만 teamai 의 것으로 본다멤버가 직접 만든 skill 과 rule 은 쓰지도 지우지도 않는다
  • 판정 규칙은 src/resources/delivered-copies.ts 의 classifyCopy 와 머리 주석에서 옮겼다. 대상은 skill, rule, agent 사본이다.

그래서 사본을 한 번 고친 멤버는 그 뒤로 팀의 변경을 자동으로 받지 못한다. 팀 판으로 돌아가려면 사본을 지우고 pull 하면 된다.

팀 저장소의 PR 리뷰가 agent 설정의 배포 승인이 된다

머지가 곧 배포이고, 사본 충돌에 push 는 경고만 낼 뿐 막지 않는다. 그래서 설정 관리에서 바뀌는 일마다 도구가 맡는 부분과 팀이 정할 부분이 갈린다.

리뷰 기준PR 본문에 자원 이름 목록만 적는다diff 에서 지워지는 줄이 팀의 최근 변경인지 본다
머지 전 시험pull --team-ref <branch> 로 한 작업공간을 PR branch 에 고정할 수 있다큰 rule, hook 변경은 리뷰어가 고정해서 써 본 뒤 머지한다

PR 이 승인 단계가 되려면 git host 와 팀 설정이 받쳐야 한다

3장의 고리는 PR 이 열리고 기본 브랜치가 막혀 있어야 승인 단계로 동작한다. 그 전제가 빠지는 경우마다 달라지는 것과 할 일이 다르다.

  • provider 가 git 이면 PR 이 생기지 않는다init --provider git 을 쓴 멤버의 push 는 branch 만 올린다. PR 은 git host 에서 손으로 열어야 하고, PR 생성이 실패한 경우에도 branch 는 남는다.
  • 기본 브랜치 보호는 도구가 확인하지 않는다src 에서 host 의 branch protection 을 조회하는 코드를 찾지 못했다. 쓰기 권한이 있는 멤버는 리뷰를 건너뛸 수 있으니 host 의 보호 규칙을 직접 확인한다.
  • enforced rule 은 이 커밋의 코드가 읽지 않는다문서는 sharing.rules.enforced 에 넣은 rule 을 멤버가 지울 수 없다고 적는다. src 에서 이 값이 나오는 곳은 schema 정의와 init 의 기본값뿐이다. 지운 rule 은 다음 pull 이 다시 쓰지만, 고친 rule 은 4장 판정대로 남는다.
  • --team-ref 로 고정한 작업공간은 push 하지 않는다리뷰어가 PR branch 를 써 보는 동안 그 작업공간에서 고친 것은 나가지 않는다. 고정을 풀면 push 가 기본 브랜치로 보낼 편집을 알려 준다.
  • 머지된 변경은 다음 세션부터 기대한다세션 시작 pull 은 host 가 기다리지 않는 분리 프로세스로 돈다. 문서도 도착 시점을 팀원의 다음 세션으로 적는다.
