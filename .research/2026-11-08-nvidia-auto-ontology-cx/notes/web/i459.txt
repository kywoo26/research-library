Summary\r\n\r\nThe function `prune_disjoint_semantic_fks` in `auto_ontology/semantic/semantic_fk.py` finds\r\nsemantic keys with no shared values. It uses this condition: `{sc} IN (SELECT {tc} FROM {target})`.\r\n\r\nIf the source column and the target column have different types, DuckDB does not do the\r\ncomparison. It raises a `BinderException`. The `except` branch writes\r\n`semantic FK overlap check skipped` to the log at INFO level, and the key stays.\r\n\r\nAfter that, `select_semantic_fk_join_defaults` enables one key in each group of source table and\r\ntarget attribute.
