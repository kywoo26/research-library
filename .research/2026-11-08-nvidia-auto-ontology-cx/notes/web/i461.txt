Summary\r\n\r\n`check_answerable` gives a low coverage grade to a question that names a value in the data, for example a repository name. The grade does not compare the named value with the rows. Thus the check can decline a question that the data can answer.\r\n\r\n### Version\r\n\r\n- auto-ontology at `2a24f5d`.\r\n- DuckDB connector, one database.\r\n- Chat models: `nvidia/nemotron-3.5-lightning-30b-a3b` and `nvidia/nemotron-3-ultra-550b-a55b`, with thinking off.\r\n- Coverage bar: 0.6.\r\n\r\n### What we see\r\n\r\nOur catalog has a `repo_name` column. The column holds the names of 25 repositories. Each of these questions names one repository, and the data can answer each question:\r\n\r\n| Question | Coverage | Result |\r\n| --- | --- | --- |\r\n| Which harness version does chorecraft run? | 0.5 | Declined |\r\n| How many commits does infoFlows have? | 0.5 | Declined |\r\n| How many tasks does the plan of astrolabe wave W118 list? | 0.5 | Declined |\r\n| How many waves does gemini_extender have? | 1.0 | Passed |\r\n| What was the final review verdict of merlin_alchemized wave W060? | 1.0 | Passed |\r\n\r\nThe full chat pipeline gives the correct answer to all five questions.\r\n\r\nFor \"Which harness version does astrolabe run?\", the extraction step gives two phrases: `astrolabe` and `harness version`. The grade is 1 of 2. When we change the question to \"the astrolabe repository\", the extraction step gives `astrolabe repository`, and the grade is 1.0.\r\n\r\nWe ran each question set three times on three configurations. The result is not stable. Sometimes the model does not extract the name, and then the question passes.\r\n\r\n### Cause\r\n\r\n1. The extraction prompt tells the model to keep \"named constants\" as phrases (`auto_ontology/retrieval/entity_coverage/prompts.py:122-123`). A repository name is a named constant, so the model keeps it as a phrase.\r\n2. Each phrase is compared with the column-attribute embeddings. A phrase is covered when its distance is 0.75 or less (`DEFAULT_MAX_DISTANCE` in `state.py:17`).\r\n3. The embedding text of an attribute contains its name, its term, its description and some sample values (`auto_ontology/semantic/embed.py:238-250`). A bare value is not near this full text. In our runs, no repository name came within 0.75.\r\n4. The grade does not look up a named value in the rows.\r\n\r\n### What we tried\r\n\r\nWe added a glossary entry for each repository, for example \"the astrolabe repository (repo_name = 'astrolabe')\". The extraction prompt uses the glossary. This did not correct the grades on either model. We did not try other glossary texts.\r\n\r\n### Possible fix\r\n\r\nWe did not test these changes:\r\n\r\n- Do not grade phrases that are values.
