# 독자 시험

하네스를 바꿨을 때 문서가 더 잘 읽히게 됐는지를 인상 대신 같은 자로 재는 방법이다. 2026-10-25 에
기준선을 잡으며 쓴 절차를 그대로 적었다. 문서 한 편을 검증하는 단계가 아니라, 하네스 변경 전후를
비교할 때 몇 편에 한 번 돌리는 측정이다. 점수를 문서마다의 게이트로 쓰면 작성자가 독자 에이전트에
맞춰 쓰게 되므로 게이트로 쓰지 않는다.

## 무엇을 재나

| 지표 | 재는 법 | 쓰임 |
|---|---|---|
| 소유자 첫 화면 | 소유자가 표지와 요약만 보고 문서의 답을 한 줄로 적고, 가독성(상/중/하)과 손볼 정도를 고른다 | 기준값. 에이전트 점수는 이것을 따라가는지로 믿을지 정한다 |
| 에이전트 첫 화면, 훑기, 전체 | 아래 절차의 점수 | 문서 사이와 하네스 버전 사이의 비교 |
| 전이 | Q5 점수 | explainer 가 원문에 없는 경우를 예측하게 하는지 |
| 표지 비교 | 같은 원장으로 표지만 다시 쓴 판과 원래 판을 좌우를 섞어 나란히 보이고 소유자가 고른다 | 표지 규칙 같은 좁은 변경 |

메시지가 보이는지는 에이전트 점수로 재지 않는다. 기준선에서 에이전트 독자는 표지가 설명만 할 때도
함의를 스스로 추론해 메시지를 찾았다고 적었다. 소유자의 첫 화면 판정과 표지 비교로 잰다.

## 절차

1. **재료.** 문서마다 `node scripts/render.mjs research/<slug> --out=<dir>` 로 장별 화면을,
   `node scripts/doc-text.mjs research/<slug> --scan` 과 그냥 실행으로 훑기와 전체 텍스트를 만든다.
2. **문항.** 에이전트 하나가 문서를 열지 않고 원장(`claims.jsonl`, `evidence.jsonl`, `sources.jsonl`)과
   `run.json` 의 질문만 보고 문서마다 다섯 문항과 정답을 쓴다. 문서를 보면 문서가 강조한 것을 문서에서
   찾는 시험이 된다. Q1 은 기록된 질문이고 정답에는 결론을 가장 크게 바꾸는 조건 하나만 넣는다.
   Q2~Q4 는 원리와 조건, Q5 는 원문에 없는 상황이다. 한 문항은 한 가지만 묻고, 정답마다 필수 요소
   한두 개와 claim id 를 단다. 정답 파일은 저장소 밖(`~/.cache/` 아래 등)에 두어 독자가 열 수 없게 한다.
3. **읽기.** 약한 모델(haiku)이 페르소나 둘로 문항을 모른 채 읽는다. 첫 화면 스크린샷 두 장을 보고
   80단어, 훑기 텍스트를 읽고 150단어, 전체 텍스트를 읽고 300단어의 메모를 남긴다. 앞 메모는 고치지
   않는다. 메모 분량을 묶어 두는 것이 기억 병목이다. 문항을 미리 주면 찾기 과제가 되어 점수가
   천장에 붙는다.
4. **답.** 새 컨텍스트의 haiku 가 메모만 보고 단계마다 다섯 문항에 답한다. 메모에 없으면 "모름".
5. **채점.** 에이전트 하나가 모든 문서를 같은 기준으로 매긴다. 필수 요소가 다 있으면 1, 일부면 0.5,
   틀리거나 모름이면 0 이고, 원장과 어긋난 진술은 따로 표시한다. 소유자가 적은 한 줄 답도 이름을 가린
   채 같은 정답으로 채점한다.
6. **소유자.** 문서마다 탭을 열고 한 편씩 묻는다. 결과는 소유자 답을 다 받은 뒤에 보여 준다.

비용은 다섯 편 기준 문항 17만(sonnet), 읽기와 답 76만(haiku), 채점 14만(sonnet) 토큰이었다.

## 결과를 둘 곳

문항, 메모, 답, 채점, 스크린샷은 git 이 무시하는 `_scratch/` 나 `.research/<slug>/notes/` 에 둔다.
비교에 쓴 숫자와 그 결론은 하네스를 바꾸는 PR 본문에 적는다. 2026-10-25 기준선과 그때 고친 표지
규칙의 경위는 `method-provenance.md` 의 "Why the cover leads with what the subject is" 에 있다.
